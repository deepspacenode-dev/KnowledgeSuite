# Drv Knowledge Suite V2.0.3 内网部署与验收

## 1. 适用范围

本手册用于 Linux x86_64 + Docker Compose 内网环境，RAGFlow 当前统一地址为 `http://10.222.120.25/`。发布物中所有 API Key、Widget Auth、BookStack Token 和 Worker Key 均为空，只能写入目标服务器的本地 `.env`。

V2.0.3 不重新初始化既有 BookStack，不覆盖 MariaDB 文章数据或 `/config` 中的附件、主题和用户文件。升级使用不可变镜像和现有数据卷，禁止在正式机器执行带新空卷的初始化 Compose。

## 2. 升级前必做备份

1. 记录当前 BookStack 镜像 digest、Compose 文件和 `.env` 的存放位置。
2. 使用 `deploy/scripts/backup.sh` 导出 MariaDB，并完整备份 BookStack `/config`。
3. 检查 SQL 备份非空，抽查 `/config/www/uploads` 和配置文件可读。
4. 保留 V2.0.2 镜像和当前容器名，直到 V2.0.3 完成一个验收周期。

## 3. 离线制品导入

```bash
sha256sum -c SHA256SUMS.txt
./deploy/scripts/import-oci.sh . SHA256SUMS.txt
docker image inspect drvknowledge/bookstack-governance:2.0.3
docker image inspect drvknowledge/worker:2.0.3
docker image inspect drvknowledge/fake-ragflow:2.0.3
```

不使用 `latest`，不在内网环境执行在线 `pip install`/`npm install`。

完整包的 `extras/ragflow-manuals-cleaned-v1.1.0-20260904.zip` 包含已通过 RC 的 A2/A3/A5/E2/M3 清洗结果、审计记录、清洗器及可直接上传 RAGFlow 的 30 个 Markdown 分片。它是迁移辅助材料，不会由 Compose 自动写入或覆盖正式数据集。

## 4. 目标环境配置

从 `deploy/.env.example` 复制本地 `.env`，至少确认：

```dotenv
DRV_BOOKSTACK_IMAGE=drvknowledge/bookstack-governance:2.0.3
DRV_WORKER_IMAGE=drvknowledge/worker:2.0.3
RAGFLOW_BASE_URL=http://10.222.120.25
RAGFLOW_WEB_URL=http://10.222.120.25/
RAGFLOW_API_KEY=<目标环境密钥>
RAGFLOW_CHAT_BASE_URL=http://10.222.120.25
RAGFLOW_CHAT_API_KEY=<可选的独立 Chat 密钥>
RAGFLOW_CHAT_ID=<Chat ID>
RAGFLOW_WIDGET_ENABLED=true
RAGFLOW_WIDGET_BASE_URL=http://10.222.120.25
RAGFLOW_WIDGET_PATH=/chats/widget
RAGFLOW_WIDGET_SHARED_ID=<分享 ID>
RAGFLOW_WIDGET_AUTH=<仅保存在目标 .env>
```

`RAGFLOW_WIDGET_ALLOWED_PATHS` 默认只允许 `/chats/widget,/next-chats/widget`。先执行：

```bash
python3 tools/ragflow/check_widget.py --json
```

只有探针确认页面存在、没有跳转到登录页且 RAGFlow 允许 BookStack 域名 iframe 嵌入后，才开启正式用户。

当前地址使用 HTTP，Widget Auth 会出现在浏览器 iframe URL 中。正式长期运行应优先为 BookStack 和 RAGFlow 部署 HTTPS，并定期轮换 Widget Auth；不得把真实 URL 查询凭据贴入文档或发布包。

## 5. Chat Profile V2

先查看脱敏差异：

```bash
python3 tools/ragflow/apply_chat_profile.py --profile contracts/ragflow/chat-assistant.v2.json --dry-run
```

确认 Chat ID、数据集和 Prompt 后才执行：

```bash
python3 tools/ragflow/apply_chat_profile.py --profile contracts/ragflow/chat-assistant.v2.json --apply
```

该 Profile 限制跨领域、跨芯片和跨平台证据混用。当证据不足或冲突时，对话应明确说明不确定性并要求用户补充信息。

如接入既有 BookStack，使用部署复盘中的容器改名切换方式，必须保留原 MariaDB 和 `/config` 卷映射，不要创建同名新卷。

## 7. 功能验收

### 7.1 治理中心

- 质量问题和 RAG 状态显示文件名，不以内部 ID 代替。
- 质量问题的“查看原文”可打开正确 BookStack 文章；芯片手册章节显示“查看章节原文”。
- 门禁帮助为中文，可解释扣分项、阻断结论和修复方法。
- 全部页面审批通过后，“一键入库 RAGFlow”可点击；重复点击幂等，并显示每页中文结果。
- 不满足门禁、非 Wiki 或非 `【AI】` 书架时必须拒绝入库。
- 知识缺口删除只对管理员开放，必须输入原因，操作后可查到审计记录。
- 知识资产删除、RAGFlow 跳转按钮、Markdown 导出和解析状态回查可用。

### 7.2 悬浮助手

- 单击小人打开官方 Widget，不再打开自研 Chat 表单。
- iframe 按需创建，关闭后可再次打开，加载失败有明确提示。
- 小人周围不显示蓝色虚线圆框；键盘用户仍可使用可访问的焦点样式。
- 默认 iframe 不具有麦克风/摄像头权限。

### 7.3 A 端 Recall V4

```bash
kb recall -q "RTL8367S PHY link up 但是无流量" --mode live --json
kb evaluate --mode live --testset <内网回归集> --json
kb feedback --trace-id <recall-trace-id> --label missing_answer --reason "缺少当前平台案例" --json
```

- 网络查询不得返回明确 Sensor/ISP 文档，芯片冲突候选必须出现在 trace 拒绝原因中。
- 每个公开结果必须有 BookStack URL；坏链接使用 `bad_link` 反馈。
- `answer_status` 只能为 `ok` / `no_match` / `ambiguous_match`。
- 正常召回只保存脱敏 trace，不自动制造用户反馈；`irrelevant` 和 `missing_answer` 会形成知识缺口事件。

## 8. 回滚

1. 停止 V2.0.3 Worker，防止切换期间领取新任务。
2. 将 BookStack 容器切回原 V2.0.2 固定 tag/digest，仍挂载原 MariaDB 和 `/config`。
3. 如果仅前端异常，清理 BookStack/Laravel 缓存并确认静态资源 cache key 恢复为旧版。
4. 只有已证明数据损坏时才恢复 SQL 和 `/config` 备份；不得为了前端回滚盲目覆盖生产数据。
5. 使用 `deploy/scripts/rollback.sh` 后重新执行登录、文章读取、治理摘要和 RAG 状态冒烟。
